00

概览

盯盘侠是一款 A 股盯盘 H5。这一版把界面从「能用」重做成「有据可依」—— 所有颜色、字号、间距都不是拍出来的，而是从用户习惯推导、再用脚本验算过的。

配色缺陷

47 → 0

v1 有 47 组组合达不到 WCAG 2.1。逐条修完后实测 0 不达标。

字号档位

18 → 8

v1 实际用了 18 种字号、8 种字重，其中 620/650/680 肉眼分不出来。

硬编码颜色

27 → 0

散落在组件里的 13 个色值绕过了令牌体系，现已全部收编。

这一版改了什么

v1 的配色问题不在「颜色选得不好看」，而在一个颜色承担了太多角色。 比如 --accent 同时当按钮底、焦点环、链接文字和图标色 —— 结果四个场景全都不达标（2.58–3.05:1）。

v2 按角色拆色。每个色相拆成四个独立令牌： 填充底、文字色、胶囊文字、胶囊底，各自独立达标，互不借用。 数值全部由 scripts/solve-tokens.mjs 在 OKLCH 空间反解得到 —— 手工目测的极限大约在 3:1，差的那 1.5 眼睛判断不出来。

怎么验证这套规范

  • 1

    npm run audit:contrast

    按 WCAG 2.1 逐组合实测对比度，同时扫描绕过令牌的硬编码颜色。退出码非 0 即表示有缺陷。

  • 2

    npm run check

    静态自检：模块引用、Service Worker 预缓存清单、图标名、事件处理函数覆盖。

  • 3

    npm run e2e

    真实 Chrome 跑端到端，其中包含「渲染出来的文字对比度是否真的达标」—— 只验令牌不够，令牌对了但组件用错角色，用户看到的还是糊的。

01

用户与信息架构

界面上的每个决定都该能追溯到一条用户习惯。这一节先把习惯写清楚， 后面所有取舍都从这里推导。

三类典型用户

盘中快查型

上班族 · 交易时段偷空

9:30–11:30 / 13:00–15:00 之间打开，每次 20–60 秒。多数时候在电梯、地铁、会议间隙，单手操作。

要的是一眼看到「今天赚了多少」和「持仓里谁在动」。

盘后复盘型

有闲的散户 · 晚间

20:00–23:00，有 10–30 分钟。愿意看净值曲线、AI 分析和机会扫描，但不想读长文。

这也是深色模式使用占比最高的时段。

条件盯守型

设了提醒等触发

自己划了线（到价、涨跌幅、技术指标），剩下交给系统。提醒太多会麻木，所以宁少勿滥。

用户习惯观察设计对策

设计原则

信息架构

五个一级页签 + 两个二级页。一级页签用固定底栏承载，二级页从右侧推入并保留返回。 层级刻意压得很浅 —— 快查型用户平均只待 40 秒，藏太深等于没有。

02

色彩

莫兰迪静物画的灰调：所有颜色掺一层暖灰，饱和度压到最低，明度拉开但不刺眼。 文字用暖炭灰而非纯黑，背景用燕麦米白而非纯白 —— 高对比虽然「清楚」， 但久看会累，而且廉价。

每张色卡下方的比值是实测对比度，不是标注值。 页面加载时用 WCAG 2.1 相对亮度公式现算，所以它永远和令牌文件一致。 点击色卡可复制令牌名。

中性面 · 按空间角色命名

v1 用的是 surface-1/2/3 这种编号。编号的问题不是丑，是看不出该用哪一个， 最后只能靠翻代码猜。改成空间角色名之后，一眼就知道这块面在界面上处于什么位置。 浅色主题下「越高越亮」：页面底最暗，浮层最亮。

文字 · 四级

解算基准取的是最不利的那个面（浅色下是最暗的嵌入块，深色下是最亮的浮层）。 这样得到的是一个强保证：任何一层文字放到任何一层中性面上都 ≥4.5:1，不必再记搭配表。

语义色 · 六色相 × 四角色

这是 v2 最关键的结构变化。每个色相拆成四个角色，各自独立达标，不跨角色借用 —— v1 的坑就是借出来的：填充底和文字色共用一个值，必然有一头不达标。

涨跌色 · 中国市场习惯

涨用红、跌用绿，与欧美相反。莫兰迪化之后是陶土红与灰绿，久看不累。 但颜色不能是唯一信号：同时配 +/− 符号与箭头， 色觉障碍用户才读得出来。

描边 · 四级

这里有一条容易搞混的界线：分隔线是装饰性的（WCAG 1.4.11 明确豁免）， 可以做到 1.1:1 只负责分组；但输入框、开关的边框承载「这里可以操作」的信息， 属于非文本 UI 组件，必须 ≥3:1。这两件事不能共用一个值。

焦点环

两层结构：内层用页面底色把控件和环隔开，外层才是强调色。 单层环压在彩色按钮上会糊在一起看不清。

03

字体

字阶只留 8 档。超过 8 档就会出现「13 还是 14」这种没人能稳定判断的选择， 最后变成随手写 —— v1 实际用了 18 种字号，就是这么来的。

字阶 · 8 档

正文基准定在 15px。中文在 14px 以下笔画开始糊，15px 是移动端的实用下限。 最小字号 11px，不再往下 —— 再小就只是为了塞内容，不是为了让人读。

字重 · 只用三档

v1 用了 400/500/550/600/620/650/680/700 八种字重。 问题是中文字体通常只有 400 和 700 两个真实字重，620 和 650 会被渲染成同一个 —— 写了等于没写，还让人以为有区别。收敛到三档，每档都有明确用途。

04

间距与圆角

间距全部落在 4pt 栅格上。8pt 太粗，表达不了 12px 这种高频间距； 4pt 是既能表达足够层次、又不会产生「13 还是 14」困惑的最小栅格。

间距 · 4pt 栅格

例外：小于 8px 的微调（1px 描边、2px 间隙、3px 内缩） 属于光学补偿，不进栅格。栅格约束的是结构性间距， 不是禁止所有非 4 倍数。

圆角

莫兰迪的柔和感很大一部分来自圆角。规律是元素越小圆角越小： 26px 的徽标配 6px，卡片配 18px，胶囊全圆。乱配会让小元素显得臃肿。

05

阴影与层级

莫兰迪要的是「轻」，所以阴影极淡，而且带暖色 —— 用中性灰的阴影压在米白底上会显脏，像蒙了层灰。

阴影 · 四级

阴影只用来表达层，不用来装饰。同一屏内最多出现两级 —— 三级以上用户就分不清谁在谁上面了。底栏用 --shadow-nav， 它比普通阴影多一条向上的实线，因为底栏需要一条明确的分界而不是模糊的过渡。

层级 · z-index

z-index 用命名令牌而不是随手写数字。随手写 999 的下场是三个月后 所有人都在写 9999。

06

图标

全部手写 SVG，零图标库。统一 24 网格、1.7 描边、圆头圆角连接 —— 描边粗细不统一是「拼凑感」最主要的来源。

规格

  • 画布 24×24，实际尺寸由 CSS 控制
  • 描边 1.7，stroke-linecap: round，stroke-linejoin: round
  • 全部 fill: none，纯线性，不用填充图标
  • 颜色继承 currentColor，不写死

尺寸

  • 21px — 底栏导航
  • 18px — 顶栏按钮
  • 15px — 区块标题、提示条
  • 13px — 行内小图标
  • 9px — 步骤点等极小场景

可点区域

图标视觉尺寸最小 13px，但可点区域一律撑到 44px。 做法是用 padding 或伪元素扩展命中区，视觉上仍保持紧凑 —— 靠加大图标来满足触控目标会让界面显得笨重。

07

动效

动效只做一件事：说明状态怎么变的。 不解释变化的动画就是噪音，而且会让盯盘的人觉得卡。

时长 · 三档

令牌值用途

超过 320ms 用户就会感到卡顿。盯盘场景尤其敏感 —— 用户要的是「现在是多少」，不是「它怎么变成这个数的」。

缓动 · 四种

入场用 ease-out（快起慢停），退场用 ease-in（慢起快走）—— 这与物理直觉相反，但符合注意力规律：出现时希望它快点到，消失时希望它别磨蹭。

降级

系统开启「减弱动态效果」时，全部动画时长压到 0.01ms。 这不是可选项 —— 前庭功能障碍的用户会因位移动画产生眩晕， 而这类人群在长期盯盘的用户里并不少见。 

@media (prefers-reduced-motion: reduce) {
  * { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; }
}

08

组件

每个组件都列出完整状态。只画「正常态」的规范是不完整的 —— 真实界面里用户看到的一半时间都是聚焦、禁用、加载、错误这些状态。

10

可访问性

审美可以主观，可访问性是硬指标。这一节的数据全部由脚本实测， 页面加载时在浏览器里现算一遍 —— 不是抄进文档里的死数字。

对比度实测

阈值依据 WCAG 2.1：正文 4.5:1（SC 1.4.3 AA）、 大字与图形化文字 3:1、 非文本 UI 组件 3:1（SC 1.4.11）。 纯装饰性元素（分隔线、进度槽底）不受约束，单列为「豁免」。

组合实际渲染对比度阈值判定

触控目标

最小 44 × 44

iOS HIG 与 WCAG 2.5.5 的共同底线。下面三个方块都是 44px 命中区， 但视觉尺寸分别是 44 / 34 / 24 —— 命中区靠 padding 撑， 不靠把图标画大。

间距同样计入命中区

相邻可点元素之间的空隙不算命中区，所以两个 44px 按钮挨在一起时 必须留出足够间隙，否则用户会点到隔壁。 列表行高一律 ≥56px，正是这个原因。

语义与焦点

场景做法

已知取舍

  • !

    涨跌色对红绿色觉障碍不友好

    红涨绿跌是市场约定，不能改。补偿手段是同时给出符号： 涨跌数字带 +/−，涨跌停带 ▲/▼， 指数卡带箭头图标。颜色是加速识别的捷径，不是唯一通道。

  • !

    半透明毛玻璃背景会降低实际对比度

    顶栏与底栏用了 backdrop-filter + 半透明底。 透过去的内容会拉低实际对比度，所以这两个面上的文字 只用 --ink / --ink-2，不用 --ink-3。 不透明度也压在 88% 以上，把影响控制在可忽略范围。

  • !

    装饰性分隔线远低于 3:1

    --line 与 --line-soft 只有 1.1–1.3:1。 这是刻意的：它们只做视觉分组，去掉后信息依然完整， 属于 SC 1.4.11 明确豁免的装饰元素。 但同样的颜色不能拿去做输入框边框 —— 那种场景必须用 --line-strong。
